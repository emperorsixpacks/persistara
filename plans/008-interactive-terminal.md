# 008 — Make the terminal the primary workspace

Priority P0. User direction: the CLI is the most important product surface; visual redesign is deferred until the workflows work. This milestone delivers a native interactive terminal for the existing configured agent, without NEAR AI credits or browser dependency.

Implement `persistara` / `pnpm cli`: interactive help, original-owner connection through the external official NEAR CLI keychain, finalized status, durable mission creation/run/resume/inspection/review, activity, signed specialist request/import/review/settlement/reconciliation, local memory recall/rebuild, and discoverable recovery/specialist operational commands. Reuse the same owner/mission/commerce services, scope, canonical journals and policy checks as the console. Extract common local-workspace construction rather than duplicating the engine.

An initial native login uses a distinct domain-bound NEP-413 challenge, exact original owner key and expiring in-memory session. Never import/export an owner wallet key, persist session credentials, or request a seed phrase. Restricted runtime and uploader credentials remain isolated as before. Every new effect requires current owner/session/authority checks; every financial or owner-wallet action has an exact review before persisted handoff. Unknown outcomes reconcile existing operations only. Noninteractive approvals must bind the exact displayed review digest; off-chain login consent is separate from cost authorization.

Terminal output treats all input and captured content as untrusted, escapes terminal control/bidirectional characters, limits rendered excerpts, and never logs secrets/signature proofs. EOF, Ctrl+C and SIGTERM stop the owned worker gracefully while retaining progress. Resume selects the durable mission ID, not a newly generated operation. Terminal command history is not persisted. Existing fixture/live distinctions remain explicit.

First complete workflow: connect -> create a zero-spend source mission -> run -> inspect -> review -> exit -> reopen the same completed mission in a fresh terminal. Test interruption and remaining-source resume, exact quote/delivery review, rejected financial approval, uncertain wallet handoff and output injection. Run full TypeScript, browser regressions for shared setup, and contract checks. Verify a real public-source mission through the actual terminal and external CLI signer without an upload/payment/inference call; do not require browser/off-device acceptance to progress the terminal.

AI conversation/reasoning, conversational transcript resumption, new-agent enrollment wizard, daemon lifecycle, Telegram and a remote specialist transport remain separate work. Ordinary text must not receive a fake model answer. `init` in this milestone checks/guides the existing configuration; it must not claim to create/register a new agent. The web interface remains available, with styling unchanged.

## Completed milestone — 2026-11-08

The native entry point, shared workspace, external wallet adapter, in-memory CLI-domain owner authentication, interactive shell, structured commands, exact approvals, terminal escaping and graceful source interruption are implemented. `pnpm check` passes 220 TypeScript tests in 33 suites; browser regressions pass 11 tests; contract checks pass formatting, Clippy, 34 Rust unit tests and six deployed-WASM sandbox scenarios. No contract change or redeployment was needed.

Actual terminal acceptance used the registered public-testnet owner through the official external CLI keychain, listed saved missions and rebuilt the committed memory cache through read-only NEAR/0G access. A new real source mission was stopped with SIGTERM after its first committed capture (exit 130), then resumed in a fresh native CLI process. Both sources finished with one attempt each; the first capture was unchanged. Exact-digest review and another-process reopening retained the completed artifact. No inference, upload or public transaction occurred. Sanitized evidence: [native-terminal-2026-11-08.json](../docs/evidence/native-terminal-2026-11-08.json). Native owner controls and financial failure/reconciliation boundaries are covered by fixture/service and deployed-WASM tests; this acceptance did not submit another public payment or owner-control transaction. Browser-provider approval and physical off-device recovery remain unverified.
