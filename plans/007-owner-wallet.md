# 007 — Connect the owner wallet without importing its key

Active scope: a local owner console for the existing configured testnet agent. No AI credits, public hosting, owner-key import, new contract deployment or automatic public transactions.

Read PRODUCT, ARCHITECTURE, SECURITY, plans 004/006 and the pinned wallet SDK before implementation. Preserve the original registration key: another full-access key on the same account does not satisfy contract owner checks.

Deliver one complete workflow for the already registered agent: connect an external testnet wallet, authenticate a one-time origin/account/contract-bound NEP-413 challenge, inspect finalized authority/runtime/backup readiness, review an owner pause/resume request, sign externally, persist and reconcile the matching transaction, then observe final state. The pinned NEAR Connect 0.12.0 API advertises a signTransaction feature flag but exposes no offline signing method on NearWalletBase. Use its documented signAndSendTransaction, persist dispatch before wallet handoff, and require a wallet hash to resolve a lost response. No unsigned/signed-byte or owner-nonce allocation guarantee is claimed. Broader new-agent enrollment and prepared rotation execution follow this first owner connection/control workflow.

The server binds only 127.0.0.1, enforces exact Host/Origin, bounded JSON, HttpOnly SameSite cookies, short-lived server-side sessions and CSRF protection. No wallet private key, uploader key, memory key, recovery secret or filesystem path is returned to the browser. Backup checks remain local; off-device custody is never inferred. An unavailable RPC, wrong wallet/key/network, expired/replayed signature, unsupported signing method or pending transaction fails closed. Existing runtime keys cannot authenticate as owner.

Every owner effect has an immutable operation ID/request digest, one canonical private SQLite journal, owner/account/contract/action bindings, a finalized nonce lower bound and persisted outcome. The wallet allocates the actual nonce and broadcasts; the server does not sign or broadcast. Restart, browser cancellation, disconnect and lost responses cannot silently authorize replacement effects. Only finalized matching transactions with a newer nonce count as confirmed. Changed or non-final results remain unresolved. Unknown wallet calls without a recoverable transaction hash can remain fenced indefinitely.

Validate with meaningful authentication, origin/CSRF, payload/scope, concurrency and interrupted-operation tests; deployed-WASM owner workflow; browser desktop/mobile tests with an explicitly labeled fixture wallet; production build and bundle secret scan. Real browser-wallet approval remains a distinct acceptance gate if the environment has no usable wallet/browser surface. Run pnpm check and contract checks. Update plans/README and document exact implemented limits before commit/push/sync.
