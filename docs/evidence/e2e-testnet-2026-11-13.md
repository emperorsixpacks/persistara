# End-to-end testnet run, 2026-11-13

Run with a **throwaway** faucet account, never the project owner's account or key. The account holds no value; its credentials stayed in a scratch directory outside the repository.

| Step | Result |
| --- | --- |
| Create `persistara-e2e-2973211406.testnet` with the NEAR CLI 0.31.1 faucet command (checksum-verified prebuilt binary) | Created with 10 NEAR. A name without the `.testnet` suffix is refused ("A top-level account ID can only be created by registrar"). |
| `pnpm near:deploy` dry run | Planned every step, signed nothing. |
| `pnpm near:deploy --execute` | Created `authority-v2.persistara-e2e-2973211406.testnet` (5 NEAR), deployed the committed `name.owner` artifact and ran `new` in one transaction, registered `research` (agent ID `research.persistara-e2e-2973211406.testnet`), set the 0.02 / 0.05 NEAR policy, funded 0.1 NEAR, authorised the runtime key, recorded the delegate. Needed several re-runs because of dropped RPC connections; every re-run resumed from chain state. |
| On-chain code hash (`contract:fetch`, expected `A2N6rTX3eAsSmJQgo4pBy7AuiPaw8pLGmf8p7Jyw6Q4a`) | Matches the committed artifact byte for byte. This is the first live proof of the `name.owner` contract. |
| `persistara status` against the new deployment | `research.persistara-e2e-2973211406.testnet` ACTIVE, treasury 0.1 NEAR. |
| `persistara wallet add --from-near-credentials` | Stored an encrypted key (AES-256-GCM, scrypt) in a scratch key store. |
| `wallet list`, `wallet check` | Correct passphrase unlocks; a wrong passphrase is refused with AUTHORIZATION_FAILED. |
| `near:deploy --owner-from-keystore` dry run | Key read from the store through the passphrase prompt; every step reported "already", so a finished deployment is idempotent. |

Bugs this run found and fixed (with regression tests):

1. Resuming after the contract account existed demanded the full 6.5 NEAR again and refused with only about 5 NEAR left. It now requires only what is still to be spent plus a gas margin.
2. A freshly registered agent has `policy: null` on the live contract; the deploy tool crashed on it while the fixture used an empty policy object. The fixture now matches the live shape.
3. A dropped RPC connection printed only `UNEXPECTED_ERROR`; owner tools now say `NETWORK_ERROR` and to run the command again.

Not covered: the interactive `/connect` sign-in inside the full-screen app and a paid chat turn with this deployment.
